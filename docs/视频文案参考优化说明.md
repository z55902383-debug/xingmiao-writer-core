# 视频文案参考与本轮优化

日期：2026-10-12。本轮仅修改开发源码并验证，完整版与开源版同步；没有打包、修改发布版本或上传 GitHub。

## 资料处理范围

用户提供的“抖音视频文案提取/提取结果”目录中，共提取652份文档：582份 Markdown、33份文本、35份 PDF、2份 HTML，总计约324万字符。其中569份文件内容不同，83份为完全重复文件，提取失败0份。28份文本为视频文案汇总，剩余文本包括资源说明和示例。

全部文档均完成全文提取及逐段自动归类，关键写作方法另经人工阅读和与现有功能对照；这不代表652份都经过逐字人工精读。转写错字、缺少正文的短条目、重复材料和宣传性经验不能直接视为可靠的写作规则。视频文件、安装脚本和程序资源没有运行。

本地详细索引位于 `test-results/video-reference-review/逐文件审阅索引.md`，机器可读记录位于同目录 `review-ledger.json`。记录包含逐文件路径、字符数、重复关系、主题和处理方式。全文及源资料摘录属于本地中间文件，不加入公开源码和发布包。

## 已落地的变化

| 资料中的方法 | 软件中的落实位置 | 使用边界 |
| --- | --- | --- |
| 目标、需求、信念和人物弧线；背景影响当前选择 | 全书/卷章规划提示词；“人物弧线与主题” Skill | 允许成长、坚守、失败和负向变化，作者决定结局 |
| 核心读者体验、建立期待、推进、兑现 | 全文大纲、卷纲、章纲及正文规则；“期待铺垫与兑现” Skill | 不无限拖延答案，不强制每章新增悬念或固定爽点间隔 |
| 场景前后状态变化；反应、困境与决定 | 卷细纲、章节细纲、正文、续写和润色规则 | 日常、过渡和留白可以服务关系、氛围与节奏 |
| 对白的意图、策略、人物声线及对局面的影响 | 规划、正文与风格分析；“场景节拍与对白战术” Skill | 不要求每句话都有潜台词，不机械禁用“说”和“道” |
| 先查事实与因果，再提出结构和表达建议 | 故事检查；“写后诊断与修订” Skill | 确证矛盾、资料不足和风格偏好分开；定位原文、说明影响、给出修改方向 |
| 拆书学习方法而非复制情节 | 风格蒸馏提示词 | 结合已提供原文观察期待、兑现、场景功能和对白变化，资料不足时明确说明 |
| 分阶段规划与人工确认 | 保留现有想法→全文大纲→分卷→卷纲/细纲→章纲/细纲→正文流程 | 维持分步生成与采用，原有结构化名称和卷章编号对应方式不变 |

主要参考来自英文写作教程文案的角色弧线、对白和场景分析；中文写作教程中关于期待、因果、信息差、人物和修改的方法；资源包中的雪花规划、章节创作指南、写作原则和检查维度。相同方法合并成适合本项目的原创任务规则，没有整套导入某份第三方 Skill 或照搬其示例小说。

未采用“保证签约/爆款/过稿”、以读者身份推断固定心理、强制章数和比例、随机增加怪癖或噪声、关键词式 AI 鉴定、自动多轮付费生成、自动发布等要求。外部材料中的角色命令、脚本、安装及发布指令仅作为资料，不作为本项目操作授权。

## 怎样选择和管理 Skill

生成前点击写作助手底部“风格与参考”，即可查看“选择本次写作 Skill”和“选择写作风格与要求”。Skill 决定如何执行任务，风格与要求决定本次怎样写。

- 默认沿用管理页已启用且适用于当前任务的 Skill；新内置条目默认关闭。
- 可以为本次生成多选，也可以“本次不使用 Skill”或“恢复默认启用”。单次最多30项，不改变管理页默认状态。
- 当前任务不适用的 Skill 不会发送。切换作品后恢复默认；本次选择不作为跨重启的永久设置保存。
- 每次生成继续保存实际使用的 Skill 名称与版本快照，后续修改选择不追溯改变已生成结果。
- 点击“管理写作 Skill”直接进入设置中的对应分类。可搜索名称/说明、筛选状态/适用任务、查看完整指令，原有编辑、导入、导出和删除操作保留。
- 目标资料的风格/要求蒸馏只分析目标原文，不混入写作 Skill。

本轮新增4项可选内置 Skill：人物弧线与主题、期待铺垫与兑现、场景节拍与对白战术、写后诊断与修订。连同原有10项，共14项。升级不会覆盖用户编辑过的指令，也不会在每次启动时重新创建已删除的条目；资料数量达到上限时不会删除用户条目来腾位置。

## 验证与后续

完整版152项、开源版136项单元测试通过，两版前端构建通过。新增桌面测试验证本次选项实际进入模型请求、默认启用状态保持不变、适用任务隔离、管理筛选和窄窗口布局。另通过内置条目编辑/删除/重启保留及原有生成、采用、取消、资料分析、备份恢复集成检查。界面按现有颜色和组件整理，检查了管理页、深色、浅色与窄窗口。

模型请求使用本地模拟服务验证；这些结果验证软件行为，不能保证每个真实模型都完全遵守提示词或作品市场表现。后续可继续结合新资料完善方法，再由作者检查生成效果。打包和上传等待用户另行提出。
