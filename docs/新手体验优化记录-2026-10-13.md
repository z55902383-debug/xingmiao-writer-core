## 逐项处理

| 问题 | 本轮处理 | 验证与边界 |
| --- | --- | --- |
| F01 下一步任务错位 | 下一步同时设置页面、生成任务、任务分组、目标卷章和蒸馏目标；正文步骤进入编辑页。生成按钮显示具体任务名称 | 长篇回归直接点击“继续下一步”并实际生成，验证总纲→分卷→卷纲/细纲→章规划/细纲→正文；不再只验证中央生成按钮 |
| F02 初始空章拒绝采用 | 允许默认空白第1章按真实ID安全复用，并在采用章节规划时归入目标卷 | 不接管已有正文、概要、细纲或已定稿的未归卷章，也不放行其他卷或其他作品ID。失败不写入部分结果 |
| F03 改设定导致候选失效 | 生成期间提示修改资料会使候选需要重核；候选显示发生变化的资料类别，并可对照生成时与当前内容，手动编辑后保存 | 保留原有直接采用拦截。合并只更新指定单个目标字段，保留其他资料及历史快照；核对期间再次变化会拒绝保存。多卷、多章结构不整批强行合并 |
| F04 短篇路径重、等待不清楚 | 新建作品可选短篇：想法→简纲→章节概要/细纲→正文→确认完结；不要求卷纲、卷细纲。按作品规模增加规划篇幅提示；进度显示阶段和距上次输出的秒数 | 短篇默认每章1000字，可自行修改。长时间没有新内容时提示等待或停止重试。停止后的单目标规划可以手动补齐；真实模型速度和遵守篇幅要求的程度不由软件保证 |
| F05 入口和确认费力 | 空稿上方展示建议下一步；引导点击跳转后收起。规划任务默认只突出当前项，其他任务可展开。候选采用和采用后的下一步操作常驻助手下方 | 长结果不需要先滚到底才能采用。已有完整规划阅读窗口保留；候选可能含未决项时提供手动编辑入口。检查深浅主题及窄窗口 |
| F06 未决选项和因果薄弱 | 规划指令要求确定关键谜底、动机和因果。发现“待定、待确认、二选一、或者、任选”等明显表述时提示核对，单目标候选可手动编辑 | 提示是文本线索，不是语义正确性鉴定。作者仍需判断谜底是否合理、伏笔是否充分；不自动把任意一种选项当成已确认事实 |
| F07 超字数误标完成 | 书架“已完结”以作者确认为准；字数达标和定稿数量分别展示。只有所有可见章节有正文且已定稿，才能确认完结 | 改稿或新增章节后取消完结；不会因达到目标字数自动完结。进行中作品数量也排除已确认完结的作品 |
| F08 未交付就7/7 | 引导末步改为作者确认完结，不再暗示导出、备份已完成。编辑页分别显示定稿/故事资料同步、导出与备份状态 | 导出或备份取消不记录成功；备份指整个作品库。完结后正文收尾显示完结及检查/备份操作，不继续提示必须写下一章 |
| F09 继续写作回第一章 | 按作品记住最后章节；“继续写作”恢复该章及已有编辑位置记录，失效章节有安全回退 | 从头“打开”与继续写作保持区别。桌面回归验证最后章和光标位置，不把后台最新更新章节当作唯一依据 |
| F10 备份日期错一天 | 默认备份文件名使用本机日历日期，不使用UTC日期截取 | 单元测试覆盖本地13日、UTC仍为12日的边界；保存对话框仍可手动改名 |

## 故事变化核对补充

正文生成前可开关“正文生成后自动分析故事变化”，明确说明会额外调用一次模型。关闭后只生成正文，采用后仍可手动分析。

变化清单默认不勾选，提示重点核对准备、即将、已经等时间状态、推断及临时路人。可修改记录类型；关系对象为空时不能勾选后直接同步，需要补齐或改成合适类型。后端同样校验，失败会回滚，不留下部分人物或时间线记录。分析指令强调“计划发生不等于已经发生”，不将匿名路人自动升级为长期人物。

正文定稿与故事资料同步是两个状态。作者可以选择只定稿；软件不因此声称变化已核对或同步。已同步正文再次修改时提示重核。

## 使用入口与兼容

- 新书表单选择“短篇 · 简化流程”或“长篇 · 分卷规划”；原有作品默认继续原路径。
- 故事大纲的基础信息可以调整路径。有分卷的作品保留长篇路径，避免忽略已有卷章；删除分卷会保留章节，之后可以改用短篇。
- 短篇采用高级分卷规划或手动新增分卷后，切回长篇路径。现有内容不删除、不重写。
- 常驻确认区显示这份候选自己的任务及目标；切章保留历史候选时，提示它属于其他章或旧任务。
- “核对并手动合并”用于总纲、单卷大纲/细纲、单章规划/正文及世界文本。多人档案、时间线和多卷多章结果仍使用原有结构审核或重新生成。
- 备份恢复创建新副本，保留短篇/长篇路径、正文定稿和作者确认完结状态；恢复副本没有被导出过，不沿用原作品的导出完成标记。

## 验证记录

完整版160项、开源版144项单元测试通过；两版类型检查和前端构建通过。新增回归覆盖默认空章真实ID复用、跨目标拒绝、短篇直接拆章、完结条件、改稿/新增章取消完结、合并后二次变更拒绝、单卷中断补齐、关系对象校验与类型更正、本地日期。

两版桌面测试通过：

1. 长篇使用“继续下一步”走完整条规划链，生成并定稿两章，作者确认后才达到7/7。
2. 短篇采用三章概要和细纲，不创建分卷；关闭自动分析时正文只发出一次模型请求，采用后手工分析并核对变化。
3. 新增人物使旧卷纲候选失效，手动合并保留新增人物、原卷细纲与历史记录。
4. 三章定稿与作者确认完结、恢复最后章及光标、导出取消和成功、整库备份与独立副本恢复。
5. 原有正文生成/采用、记忆、改稿冲突、取消、参考分析、导出备份和重启保存的集成检查。

桌面测试使用独立测试书库和本地模拟模型，没有调用用户现有模型或修改现有作品。界面检查覆盖1460和1024宽度、深浅主题。测试证明软件的状态与请求行为，不等同真实模型的文学质量或网络性能保证。

可执行 `npm run test:onboarding:ui` 重跑新增桌面链路。详细报告保留在两版各自的 `test-results/onboarding/` 与 `test-results/planning-flow-*` 目录。

本轮结果可通过重新启动开发版体验；原安装程序仍保留原版本行为，等用户明确要求后再打包和上传。
